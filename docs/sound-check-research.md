# Sound Check requirements and evidence

Reviewed 26 October 2026. This note uses official Elgato documentation and the repository's research ledgers only. No reference app launch, recording, playback, installation, permission action or legacy implementation inspection was performed. **The user currently forbids local recording; implementation and tests using generated buffers are permitted.**

The pinned reference is **Wave Link macOS 3.4.0, build 3281**, acquired and identified in [REFERENCE.md](../research/REFERENCE.md). Its runtime inspection reached the separate vendor-driver installation gate; no reference mixer or Sound Check journey was exercised. The [3.4 macOS release notes](https://help.elgato.com/hc/en-us/articles/51888094897553-Elgato-Wave-Link-3-4-macOS-Release-Notes) add no Sound Check specification. Earlier version documentation below is evidence of intended behavior, not a test of build 3281.

## Proposed ReLink acceptance requirements

These are independently specified product requirements; where they go beyond the documented behavior above, they must not be presented as measured reference fidelity.

1. **Explicit scope.** Open Sound Check from a named source/effects workflow, show the selected source and audition output, and begin in an idle state. Opening the tool, changing a selection, restoring a studio or pressing the global studio shortcut must not start recording or playback. Support for hardware, virtual or application sources must follow each source's actual capture capability and permission state; no implicit system-audio fallback.
2. **Bounded dry clip.** Record at most 30 seconds, using a checked frame/byte budget and preallocated storage. Stop retains the exact captured length, including a partial final callback; reaching the limit stops recording visibly. Keep the clip immutable and before ReLink input effects. Do not describe already-processed hardware audio as universally dry. Empty or failed recording cannot enable Play; replacing or clearing a clip cannot expose stale frames.
3. **Audition the current settings.** Play and explicit loop controls reuse the same clip through the selected source's current effects exactly once. Gain, bypass and supported effect edits retain the clip and have defined control acknowledgements. Structural edits must either switch safely or stop with a clear explanation; they must not silently destroy the recording. Stop returns to a defined playback position. State and duration must agree with the engine, including asynchronous failures.
4. **Isolated output.** Use only the explicitly selected audition endpoint, with no default-device fallback and no writes to normal mix/broadcast destinations. The first implementation may require normal studio routing to stop before entering Sound Check and block its restart while the audition owns audio. That is a ReLink policy, not an observed Wave Link behavior. A virtual audition endpoint may itself be consumed by another app, so the UI cannot promise privacy merely because it is called a monitor output.
5. **Safe termination and ownership.** Stop, Clear, Close, source removal, destination loss and cancellation revoke audition audio. Never resume broadcasting or recording automatically on close, reconnect or restart. Retain native ownership/reservations until teardown is established; show actionable failure instead of pretending cleanup succeeded. Clearing removes both the clip and any replayable cached data. Memory-only clips, discarded on close/exit, are a conservative initial policy that must be visible to the user; cross-session clip persistence is not a documented requirement.
6. **Respect the current recording prohibition.** Implement and verify the state machine, limits, effect path and output isolation with generated PCM supplied directly to the offline path. Do not launch microphones, application/system capture, native reference playback or recording permission prompts to validate this work. Label generated samples as generated; they are not microphone recordings or native audio qualification.

## Offline proof and remaining qualification

Use independent generated stereo/impulse fixtures to check: selected-source-only capture; exact dry bytes despite non-unity effects; changed/bypassed effects applied once on replay; cap and partial-block accounting; empty/short clips; loop wrap and partition independence; clip retention during supported edits; Stop/Clear/Close and late-completion cancellation; and zero PCM on every unrelated output sink. Include failure and resource-limit cases, not only a successful cycle. Any smoothing at loop boundaries must be explicit and tested rather than silently modifying the stored clip.

The historical [acceptance ledger](../research/ACCEPTANCE.md) records a 30-second cap and narrower Sound Check tests in the superseded prototype. Those are neither Wave Link observations nor qualification of the proprietary Rust implementation. The [Rust requirements](../research/RUST-MIGRATION.md) continue to require Sound Check and independent audio-route acceptance. Generated-buffer tests can qualify the new logic; native source permissions, sustained capture/playback, independent output isolation, device recovery, both operating systems and pinned-reference comparison remain separate, unperformed checks for this workflow.

The maintained Rust source now includes a [bounded dry-clip engine](../crates/relink-core/SOUND-CHECK.md), [private audition processor](../crates/relink-audio/SOUND-CHECK-AUDITION.md), and [capture lifetime observation](../crates/relink-audio/CAPTURE-COMPLETION.md). These components have generated-buffer and fake-owner controls. The exclusive runtime lease, native record/playback handoff, final-frame submission gate and complete interface remain unimplemented. No local recording, device playback, recording permission or audio-service operation was used to develop these components.

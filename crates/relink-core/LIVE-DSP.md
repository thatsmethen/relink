# Live built-in DSP controls

`PreparedControls::compile` now prepares high-pass, gate, compressor and limiter coefficients for every input and bus alongside resolved gain/mute/solo controls. It validates the session and charges all five vectors before allocating them. Sends still carry only routing controls. `CompiledMixer::apply_controls` checks every vector length, stable channel/send ID, gain, bank sample rate and DSP record before changing any target. Rejected banks leave all gain ramps, DSP ramps, filter histories and envelopes untouched.

`DspConfig.bypass` stores four persistent `DspBypass` flags independently of each optional stage configuration. A true flag bypasses that stage without deleting its custom parameters. Missing bypass objects or individual flags deserialize as false, so older sessions retain their previous active processing. Configured parameters are validated even while bypassed. Prepared coefficients remain unchanged by a bypass toggle; only the enabled mask changes. Saving and reopening preserves both the flags and the complete settings for A/B comparison.

`PreparedDsp` is a fixed-size `Copy` value. `to_words` and validated `from_words` provide 14 `u32` words for the host's coherent atomic transport. The record contains sample rate, enable mask and scalar coefficients, including integer gate-hold samples. Wire decoding checks finite coefficient ranges, supported rate, mask and hold bounds with no allocation or transcendental functions. It validates stable processing values rather than reconstructing user-facing cutoff, decibel or millisecond settings. This is an internal runtime transport, not a versioned session-file format. Invalid decode returns `ControlError::InvalidDsp`.

Each stage has one persistent processor, one coefficient ramp and one dry/wet ramp. Audible parameter changes interpolate coefficients over `ceil(sample_rate / 200)` frames, approximately 5 ms. Each next sample advances one step; the last step reaches the exact target. Retargeting starts from the last rendered coefficients and wet fraction. Repeating an identical complete bank does not restart any ramp or reset histories. Initial compiled settings remain immediate, preserving settled static processing formulas and output.

Enabling from exact bypass adopts the requested parameters before fading in processed audio over the same 5 ms interval. This avoids passing through unused default settings while a previously bypassed stage becomes audible. Disabling retains the existing parameter target while fading to dry. Once fully bypassed, the stage performs no processing and freezes its history/envelope until re-enabled; enabling again preserves that state. A stage runs at most once per frame, and exact dry/wet endpoints avoid unnecessary blend arithmetic. Input and bus chains remain independent and retain the established high-pass → gate → compressor → limiter order.

Dynamics envelopes continue their own attack/release behavior during and after coefficient transitions. Reaching a coefficient target does not imply the envelope has reached a new steady state. Existing gate hold time remaining is preserved across updates; newly detected above-threshold samples use the current hold setting.

The fully wet limiter clamps samples to its **current interpolated ceiling**. It is still a sample-peak limiter with no lookahead or true-peak guarantee. While enabling or bypassing it, the dry contribution can exceed that ceiling. During a ceiling change, the requested final ceiling is reached only when the coefficient ramp finishes. The final sample sanitizer is fault containment, not a substitute for clipping protection.

The callback uses only inline state and preallocated bank vectors: no locks, allocation, deallocation or DSP reconstruction occur in decode, apply or render. Graph working-memory estimates include the larger inline processor states. The implementation does not supply plugin hosting, native-device validation, recording consent or Sound Check capture by itself.

Offline controls check compiled coefficient validity at every supported integer sample rate with extreme settings. Generated-buffer controls cover representative sample rates, invalid wire values and whole-bank rejection, arbitrary callback partitions, rapid retargets, identical target continuation, bypass endpoints, gate/compressor history, once-only input/bus processing, limiter transition limits, spectral change, exact memory-budget boundaries and zero callback allocation/deallocation. Persistence controls cover older sessions without bypass fields, partial flags, custom parameter round trips, validation while bypassed and dry/processed A/B for every configured stage. These are offline software controls; they make no claim about installed devices, native audio timing or perceptual quality on hardware.
